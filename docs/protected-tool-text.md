# Protected text in tools

`secret_input` returns run- or session-scoped value references. A tool data field that accepts `ProtectedText` can combine literal parts with `{ "value_ref": "run-secret:..." }` parts, for example `{ "parts": ["prefix=", { "value_ref": "run-secret:<id>" }] }`. The backend resolves those parts only in the tool handler, after any field-specific authorization, and validates the assembled value against the normal size and content limits. Target paths, resource selectors, authorization scopes, and tool results are not generic substitution surfaces. Tool implementations must explicitly opt data fields into this shared type; adding the type does not authorize external delivery or durable storage of a credential.

`write_file.content`, `edit_file.oldText`, `edit_file.newText`, and `generate_qr_code.content` accept protected text. `generate_qr_code.wifi` also accepts separate protected SSID, password, and security fields; the host validates the security type and escapes the Wi-Fi payload. QR PNGs containing protected values are user-visible artifacts but are excluded from automatic model image input and `read_qr_code` output. Argument history stores redacted QR content and protected file content, never assembled plaintext. Run-only references expire at the end of the run; session reuse still requires the user's opt-in.

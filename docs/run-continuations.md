# Active-run continuations and elevated environments

A direct message to the main session interrupts its wait for delegated work and expires open child approvals/questions without granting consent or submitting unfinished answers. The affected children skip their superseded tool batches and pause in the same run for a new parent instruction. The parent receives each pause as a task result or an appended host update, including when an earlier `task` call has already returned. The parent uses `task` with their `session_id` to continue them, or `stop=true` to cancel and join them without restarting. Other child work continues. The parent stays active after intermediate answers and receives persisted child results before it finishes. Explicit stops and parent failures still cancel and join all its children.

A correction to an active child uses the same continuation mechanism as a direct user message, with persisted parent-agent provenance. Only that child's superseded approvals/questions expire. A provider request can be interrupted; an active tool call may finish before the correction is processed. Delivery does not confirm completion and cannot undo effects. A finished child instead starts a follow-up run in the same child session; no two runs execute there concurrently.

A direct message interrupts the current model request and starts a new model request in the same run. Its instruction supersedes pending approvals and questions, but successful tool results from that run remain current evidence. Existing context budgets still shorten large tool outputs. Run-local secret references stay available only until that run ends; repeat protected-input requests reuse already answered names and ask only for missing ones. Remembering a value for later runs still requires the user's session opt-in.

The main chat and child inspector treat every user message as an answer-section boundary, including direct messages within one run. Earlier text and tool history stay above that message; new activity and text continue below it. Live output uses the same section projection as persisted messages. The model's `waiting_model` phase identifies its source user message, including in reconnect snapshots. Interrupted text is persisted immediately before the first following direct message; clients preserve timestamp precision when merging late events. An unfinished tool stays in its original section until completion. Run identity and execution remain unchanged.

Elevated shell retry detection includes the selected agent and effective sudo reference, including automatically reused references. Newly supplied authentication allows the same command to be retried; unchanged authentication or input for another agent does not reset failed-call protection. A `process.sudoAuthFailed` response discards the matching temporary sudo reference so protected input can collect a correction. Other process errors retain it, and stored personal variables are never deleted by this recovery.

For `shell_run(elevated=true)`, the backend resolves only explicitly requested environment references after authorization. The Agent passes the validated environment as structured data to its fixed privileged worker, never in the command or argument vector. The worker supplies only those values and its host-controlled execution environment to the isolated command. Sudo cannot silently drop a requested variable. The existing output redaction covers both the sudo password and explicit environment values.
